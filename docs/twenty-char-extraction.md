# 「20字小説」自動抽出（掲載前の確認用）

指定タグのnote記事から、**本文冒頭の19〜21字の作品**を抽出する機能です。初期タグは `20字小説`。冒頭のハッシュタグだけの行と、20字ではなく「参加」「20文字」「20字」を含む案内行を読み飛ばし、最初の本文行が19〜21字ならそのまま採用します。短い場合だけ連続した2〜4行を対象にします。通常の題名や本文の途中から別の作品を探す処理は行いません。

## 既存機能との関係

- 既存の `scripts/sync-candidates.py` にある公開API取得関数 `get()`、リトライ・タイムアウト、ID検証、URL生成をそのまま利用します。定義の読み込みだけで、既存の `scan()` は実行しません。
- ハッシュタグ一覧は既存と同じ `/api/v3/hashtags/{tag}/notes?order=new&page=...`。本文は `/api/v3/notes/{key}` の `data.body` だけを利用します。
- 記事一覧の `body` は抜粋のため代用しません。タイトル・説明文・作者プロフィールを本文として使うフォールバックもありません。
- 既存スクリプト、既存ワークフロー、サイトのHTML・JS・CSS、`data/` の既存ファイルは変更しません。CLIは `data/` への出力も拒否します。
- 新しいワークフローはPRのオフラインテストと手動実行だけです。定期実行・コミット・デプロイ・掲載処理はありません。
- デフォルト出力 `var/twenty-char/` はGit管理対象外です。実記事の本文や抽出結果はリポジトリに自動コミットされません。

noteの公開APIは将来変更される可能性があります。形式の検証に失敗した場合は成功扱いにせず、理由を記録します。

## 実行方法

Python 3.10以上（テスト環境は3.12）。依存パッケージはこの機能専用のファイルに分離しています。

```bash
python3 -m venv .venv-20char
.venv-20char/bin/python -m pip install -r scripts/requirements-20char.txt
.venv-20char/bin/python scripts/extract-20char.py --hashtag '#20字小説' --limit 20 --max-pages 2
```

企画の投稿期間を絞る場合は開始を含み、終了を含まない範囲で指定します。タイムゾーンのない日付・日時は日本時間です。

```bash
.venv-20char/bin/python scripts/extract-20char.py \
  --hashtag '#20字小説' \
  --since '2026-11-17T19:00:00+09:00' \
  --until '2026-11-17T21:00:00+09:00' \
  --limit 100 --max-pages 10
```

指定URLでの検証や既存データのURL一覧の再利用もできます。どちらも指定タグが実際の記事に付いているか再確認します。

```bash
.venv-20char/bin/python scripts/extract-20char.py \
  --url 'https://note.com/author/n/n0123456789ab'
.venv-20char/bin/python scripts/extract-20char.py --input data/candidates.json
```

`--input` は既存サイトと同じ `{"works":[{"url":"...","title":"...","handle":"..."}]}` 形式または記事配列。入力は変更しません。不正な行はログに残して次へ進みます。入力一覧と期間指定の併用は受け付けません。

GitHub Actionsでは毎週火曜21:00（日本時間）に自動実行します。手動実行では対象の火曜日を指定でき、`publish` をオフにすると公開データを変えずに結果だけ確認できます。抽出結果とログはArtifactに30日間保存されます。PRのテストではネットワークを使いません。

## 文字数と一行の規則

`regex==2024.11.6` の `\X`（Unicode 16.0の拡張書記素クラスタ）で、見た目の一文字を数えます。バージョンを固定して、環境による判定差を防ぎます。作者の文字列をNFC/NFKC変換して保存することはありません。

| 対象 | 数え方 |
| --- | --- |
| 日本語・全角／半角英数字 | それぞれ1字 |
| `、` `。` `「` `」` など | それぞれ1字 |
| 文章中の半角・全角空白 | それぞれ1字（行の前後は除去） |
| `か` + 結合濁点、`が` | どちらも1字 |
| `👍🏽`、`👨‍👩‍👧‍👦`、`🇯🇵` | それぞれ1字 |
| HTMLタグ・ルビの読み・画像のalt属性 | 数えない |
| HTMLの `&amp;` | デコードした `&` を1字（再デコードしない） |

noteの本文APIに `|漢字《かんじ》` または `｜漢字《かんじ》` のルビ記法が残る場合も、読みと区切り記号を除き、親文字の「漢字」だけを字数判定・掲載本文に使います。HTMLのルビと同じ扱いで、冒頭の2〜4行を結合するときも適用します。親文字の文字種・結合文字は変換しません。マーカーのない通常の括弧表現、不完全・エスケープされた記法、コード内の表記はそのまま保持します。

段落・`<br>`・テキスト中の改行を行の区切りとします。画面幅による自動折り返しは区切りません。冒頭の空段落を飛ばし、各行の前後空白を取り除きます。スクリプト・スタイル・明示的な非表示要素は除外します。

冒頭のハッシュタグだけの行は、プレーンテキスト・見出し・リンクのいずれの書式でも読み飛ばします。同じ行に複数のタグがある場合や、タグに「様」「さん」だけを添えた行も対象です。加えて、20字ちょうどではなく「参加」「20文字」「20字」のいずれかを含む冒頭行を読み飛ばします。該当する案内行が続けば繰り返しますが、作品の抽出を始めた後の行は読み飛ばしません。語の照合だけ全角英数字を正規化し、作品本文は変換しません。通常の題名や、これらの条件に当たらない挨拶・案内文は飛ばしません。記事に必要な `#20字小説` が付いているかは、本文中の表記とは別にAPIのタグ情報で確認します。

先頭の本文行が18字以下の場合は、連続した最大4行のまとまり全体を調べます。改行を除いた合計が19〜21字で、その直後が空行・画像・区切り線・埋め込み・タグだけの行・記事末のいずれかなら抽出します。同じ罫線記号が3字以上続くだけの行（`＿＿＿＿＿＿`、`---` など）も区切り線として扱います。途中に空行や画像・タグ行があるもの、5行以上続くもの、読み飛ばし条件に当たらない挨拶だけの行・案内文で始まるものはつなぎません。見出し書式は許容し、引用・箇条書き・画像説明・表・コード・リンク内の本文行は連結対象にしません。

複数行を抽出した場合は元の行を `sourceLines` に保存し、抽出結果の `text` は改行を除いた原文、`charCount` はその字数です。公開データでは元の行を半角スペース1つで結んだ一行を `text` に設定します。体裁用に追加したスペースは19〜21字の判定に含めません。

## 判定と掲載の分離

| `status` | 意味 | 掲載候補 |
| --- | --- | --- |
| `success`（成功） | 20字を抽出し、実装済みの保留条件に該当しない | はい。ただし掲載未承認 |
| `pending`（保留） | 19・21字、見出し、説明文らしい冒頭など | はい。理由を確認する必要あり |
| `failed`（失敗） | 本文なし、18字以下／22字以上、API取得失敗など | いいえ |

見出し・引用・箇条書き・画像の説明・表・コード・リンク・埋め込み内のテキストは、文字数が合っていても保留します。挨拶、ルール説明、見出し語の一部も保留条件です。指定タグ未確認、タイトルと同一の一行目、検証できない作者などのメタデータ、限定公開・非テキスト本文の信号も保留理由になります。有料記事は、公開APIで取得できる冒頭が掲載条件を満たせば対象とします。価格や有料部分への案内だけでは保留にしません。

**文字数と簡単な規則だけで、作品か説明文かを完全には判断できません。** `success` は抽出成功の意味で、抽出結果自体は全件を `unreviewed` として保存します。週次エンドロールでは、別工程の `build_twenty_credits.py` を掲載ゲートとし、火曜19:00以上21:00未満・先頭行19〜21字を掲載対象とします。見出し書式も許容します。`success`・保留理由なし、または `pending` の理由が `first_line_heading`・`non_exact_length` だけの場合に掲載します。その他の保留理由、18字以下・22字以上、失敗・収集途中の結果は掲載しません。本文と実際の字数は変更せず保存します。AI判定は利用していません。

## 週次エンドロール

- 対象タグ：`#20字小説`
- 対象時刻：当日火曜19:00以上、21:00未満（日本時間）
- 実行時刻：毎週火曜21:00（GitHub Actionsのcronは12:00 UTC）
- 掲載条件：案内行を除いた本文の先頭行、または区切りを確認できる冒頭の連続した2〜4行が19〜21字。抽出判定が `success` または見出し書式・19字／21字だけが理由の `pending`
- 並び：メンバーシップ枠、部員枠の順。各枠内は投稿日時順。主催者 `komaki_kousuke` の作品はメンバーシップ枠の最後に表示（有料会員の判定自体は変更しない）
- 保存：最新データに加え、`twenty-credits/data/archive/YYYY-MM-DD.json` に週ごとの結果を保持

会員判定は、みんなの部室に保存されている実際の会員名簿を再利用します。`sync_twenty_members.py` が公式mainのGitHub Actionsの短期認証で部室の `/api/endroll/membership` を呼び、参加作品ごとの判定を `data/twenty-char-members.json` に保存します。契約の有効期間は部室と同じ `memberPeriods` を使い、作品の投稿日時点で判定します。名簿全体・契約情報・認証情報は公開リポジトリへ保存しません。部室の名簿更新方法は従来どおりで、加入・退会の変更は新しい名簿の登録後に反映されます。

固定のテスト用会員リスト、対象日・作品の不一致、会員照合の失敗、収集上限やAPIの取得失敗があれば、古い公開データを保持したまま処理を停止します。対象作品が0件なら状態だけを `empty` に更新し、公式サイトの入口は開きません。

## 出力と確認

デフォルトの出力は以下の2つです。`--output` と `--log` で変更できます。

- `var/twenty-char/results.json`：記事ごとの判定と作品・作者の対応。各記事の処理後と終了時に、同じディレクトリの一時ファイルから原子的に保存します。
- `var/twenty-char/events.jsonl`：追記形式のログ。記事ごとのURL・文字数・判定・理由・取得エラー、重複スキップ、不正入力、収集エラーを記録します。

| 記事フィールド | 内容 |
| --- | --- |
| `key`, `url` | 不変の記事キーと正規化URL。クエリ・フラグメントを除去 |
| `title` | 記事タイトル |
| `authorName`, `handle` | 作者表示名とnote ID |
| `publishedAt` | noteが返した投稿日時（オフセットを保持） |
| `text`, `charCount` | 抽出した冒頭の作品と文字数。複数行は改行を除いて数える。本文なしなら `null` |
| `sourceLines` | 複数行の場合のみ、元の2〜4行。公開時は行間に半角スペースを1つ挿入 |
| `status`, `reason`, `reasonCodes` | 判定・日本語の理由・機械処理用コード |
| `isCandidate`, `exactly20` | 19〜21字の候補か、正式ルールの20字か |
| `reviewRequired`, `publicationStatus` | 掲載承認が必要であること |
| `firstLineKinds`, `bodySource` | 見出し等の構造と本文の取得元 |
| `checkedAt`, `firstSeenAt` | 最新確認日時と初回保存日時 |
| `error` | 取得・処理例外がある場合の詳細 |

文字数条件外の一行目も `text` と `charCount` に残します。後ろの作品を救済抽出しなかった理由を確認できます。将来の表示は `isCandidate` と掲載承認を確認して、記事の同じレコード内の `text` と `authorName` を使ってください。

同一記事はURLではなく記事キーで重複排除します。取得中の同じ記事は1回だけ処理し、再実行時は同じレコードを最新の抽出結果に置き換えます。以前成功した記事が取得できなくなった場合も、最新の失敗結果で更新して古い成功を流用しません。今回の収集に現れなかった過去レコードは残ります。

トップレベルの `summary` は保存済み全件、`latestRun.summary` は今回実際に処理した記事だけの集計です。企画・タグごとに出力先を分けてください。タグや文字数規則が異なる既存ファイル、不正な既存JSONは上書きしません。

`latestRun.stopReason` が `max_pages` / `limit` の場合、`truncated: true` で上限による部分収集を示します。タグの全記事を収集したという意味ではありません。`discovery_error` は部分結果を保存して終了コード2。個別記事の失敗はログに記録して続行し、収集自体が完了すれば終了コード0です。

```bash
# オフライン検証
.venv-20char/bin/python -m unittest discover -s tests -v

# JSONの確認（作品本文は表示せず集計だけ）
.venv-20char/bin/python -c 'import json; print(json.load(open("var/twenty-char/results.json"))["summary"])'
```
